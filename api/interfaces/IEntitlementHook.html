Interface IEntitlementHook

The product's billing. The library reserves before a run exists (reserve), or for a run written pending (reserveOnce), meters every minute, settles at the end, releases an unbilled run. settle and release are idempotent per reservation: the manager retries them until they resolve, and a repeated call after a success changes nothing.

checkRun, recover and finalize are an optional lifecycle extension for hosts opting into persisted funding.

interface IEntitlementHook {

    checkRun?(runId, phase): Promise<DispatchAllowance>;
    recover?(runId): Promise<void>;
    finalize?(reference, decision): Promise<void>;
}

Optional recordSupplierUsage

  • recordSupplierUsage(reservationId, usage): Promise<void>

  • Optional. Records what the run's supplier measured (SupplierUsage), apart from the seconds the owner is billed: the cost the run incurred, settled whatever the owner's bill, an unbilled end included. The manager calls it for every report that carries totals, before its terminal and fence checks, and for the totals a provider's usage answers at reconciliation, so it may be called again with the same or older totals: keep the largest of each. A rejection holds back no run (the report that carried the totals is applied, and a run whose worker is gone still ends): the manager keeps the totals in its stores' supplierUsageInbox, when it has one, and calls again with them at the next reconcile. Absent, nothing is recorded, and meter, settle and release behave as they do without it.

    Parameters

    • reservationId: string
