Interface RetrievalRecallReport

What a CognitiveMemoryManager retrieval reports for the recall capture, on CognitiveRetrievalResult.diagnostics.recall: trace ids, ranks, scores and a time, never a memory's text.

denseRanks

denseRanks: Record<string, number>

Each returned trace's 1-based rank in the dense leg: the order the vector recall's cognitive scores (and the graph's activation) gave the traces, before any rerank.

denseMs

denseMs: number

Milliseconds of the dense leg: the query's embedding (and its HyDE hypothesis, when one is asked for), the vector search, the scoring and the graph's activation, not the co-activation the graph records after.

Optional legs

legs?: {
    leg: RecallLeg;
    ran: boolean;
    reason?: LegAbsentReason;
    candidates: number;
    ineligible: number;
    ms: number;
}[]

Each recall leg of the retrieval, as the capture reports it: whether it ran, why not (no_embedder when the embedding manager gave the query no vector), how many candidates it returned, how many the eligibility checks dropped (for the dense leg, the trust-policy filter), and its time. CognitiveMemoryManager always sets it.

Optional ranked

ranked?: RankedRecallCandidate[]

Under hybrid: the whole recall pool in fused order, the candidates the cut at topK left out and the ones the dedupe dropped (duplicateOf) included, each with its ranks and fused score. When a rerank answered, the cut's candidates stand in the order it gave them, in the places the cut holds in that list.
