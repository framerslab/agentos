Optional budget

budget?: SpendBudget | SpendBudgetOptions

One spend budget for every call this agent and its sessions make: each provider call is checked against what is left before it is made and recorded after it, and AgentSession.recordExternalCost charges costs made outside AgentOS to it. Settings make one SpendBudget for the agent; pass an instance to share it wider. With runtime: 'gmi' every completion call a GMI makes is checked against it before it is sent, metaprompts and self-reflection included; its cognitive memory's embeddings and the learning layer's own calls are not counted. A seat's turn (sessionSeat(), or a member a launched team seats) is checked against it and charged to it beside the budget its team's call carries, and so is a team the seat's turn launches; its refusal of a seat's call runs the carried budget's onLimitReached function, as a refusal by that budget's parent does.

Optional policyTier

policyTier?: "safe" | "standard" | "mature" | "private-adult"

Caller's intended content policy tier, forwarded to every generate() / stream() / session call this agent makes (same contract as GenerateTextOptions.policyTier): on 'mature' / 'private-adult' with no explicit fallbackProviders, the auto-built fallback chain leads with the tier's uncensored legs so a content-policy refusal from the primary re-routes to a model that can complete the request, and the model router receives the tier as a routing hint. Optional responseSchema

responseSchema?: ZodType<unknown, unknown, $ZodTypeInternals<unknown, unknown>>

Optional Zod schema for validating the LLM's structured output.

When provided, the agent's generate() result includes a parsed field with the Zod-validated and typed output. JSON extraction and validation happen after generation. On validation failure, the agent retries internally (up to controls.maxValidationRetries ?? 1).

When omitted, behavior is unchanged — result.parsed is undefined. This is a non-breaking additive change.

Example

import { z } from 'zod';
const myAgent = agent({
  name: 'Extractor',
  instructions: 'Extract entities as JSON',
  responseSchema: z.object({ entities: z.array(z.string()) }),
});
const result = await myAgent.generate('Find entities in: ...');
console.log(result.parsed?.entities); // string[]

Optional memoryProvider

memoryProvider?: AgentMemoryProvider

Optional memory provider. When provided, memory auto-wires on all four agent call paths (see AgentMemoryProvider for hook contract).

  • getContext runs once per turn; its recall goes into every model call of the turn as a data block in a user-role message before the turn's own, with one static line of the system prompt that explains it.
  • observe runs as fire-and-forget once per side of an answered turn, after the result the caller receives: a schema call observes only the accepted exchange, and a stream that ends in an error is not observed.

systemBlocks?: SystemContentBlock[]

Structured system prompt blocks with cache breakpoints. When provided, they replace the assembled prompt whole: the soul's SOUL.md prose, STYLE.md and memory index are not added, and neither are instructions, name, personality and skills. Optional cache

cache?: false | {
    ttl?: "5m" | "1h";
    tail?: boolean;
}

Per-call prompt-cache control forwarded to every generate / stream / session call this agent makes (same contract as GenerateTextOptions.cache): false sends zero cache markers; { ttl: '1h' } re-times the auto markers — including the moving conversation-history tail — onto the 1-hour cache. Set '1h' for agent loops whose steps gap past the 5-minute default cache TTL (multi-minute tool executions between LLM steps), where the default-paced history marker expires between steps and every step re-writes the whole prefix. { tail: false } keeps the system-prefix markers and places no breakpoint on the messages, for a one-call-per-input agent (a judge, a classifier) whose prefix repeats and whose tail never does; a multi-turn session wants the tail, which is what reads its history back. Unset -> the provider's default marker pacing.

soul

soul: NonNullable<undefined | string | {
    content: string;
    optional?: boolean;
} | {
    path: string;
    optional?: boolean;
}>

Per-agent identity loaded from a SOUL.md workspace (the OpenClaw / aaronjmars-soul.md convention). Three forms are accepted:

  • Workspace path — points at a directory containing SOUL.md and optional companion files (STYLE.md, IDENTITY.md, AGENTS.md, MEMORY.md, examples/):

    agent({ provider: 'anthropic', soul: '~/.agentos/agents/aria' });

  • Direct file path — points at a single SOUL.md file:

    agent({ provider: 'anthropic', soul: './personas/aria.soul.md' });

  • Inline content — pass the soul markdown directly (useful for tests and ephemeral agents):

    agent({ provider: 'anthropic', soul: { content: SOUL_MARKDOWN_STRING } });

Loading semantics: when the agent is built without systemBlocks (which replace the assembled prompt, the soul's prose with it), agent() reads the soul and joins its prose into one system prompt, first the SOUL.md body, then a ## Style section from STYLE.md, then the memory/index.md catalog, before instructions, name, personality and skills. The front matter applies too: the hard limits close the system prompt as a block of their own, after systemBlocks as well; the hexaco scores render as the trait paragraph when personality is unset; and the soul's name is the name line when name is unset. Mood, voice, avatar and reasoning-trace limits have no renderer on this runtime; runtime: 'gmi' applies mood and the trace limits through its persona. A soul that fails to load, or whose front matter has a field of the wrong type, throws SoulLoadError when the agent is built. optional: true on the object forms runs the agent without it and writes one soul.load_failed log line.

See

  • loadSoul in @framers/agentos/cognition/substrate/personas/SoulLoader for the loader implementation and full SOUL.md format spec.
  • https://github.com/aaronjmars/soul.md for the cross-framework convention.

Optional pendingWritesTimeoutMs

pendingWritesTimeoutMs?: number

How long close() waits, in milliseconds, for the agent's turns still running and then for the memory writes of its turns, one deadline for both, before it compiles the wiki. Default DEFAULT_PENDING_WRITES_TIMEOUT_MS (5 seconds); 0 waits for none, and Infinity (or any wait past the longest timer, about 24.8 days) waits for them all. When the wait ends with turns or writes still pending, the compile takes what is stored and one console.warn line gives their number.

sharedMemory?: {
    as: string;
    reason: "one-persons-machine" | "operators-notes";

For one person's own machine, or an operator's own notes: every session that names no user, and every one-shot generate() or stream(), runs as the user as, so they share one memory. A session that names another user is refused, and so is opening a store that already holds the memory of another user or session.

Optional verifyCitations

verifyCitations?: VerifyCitationsConfig

Verify citations after generate() and default-runtime session calls.

When set, generate() produces the answer, then fetches sources for the user's input with the configured retriever and scores each atomic claim of the answer against them via CitationVerifier. The resulting VerifiedResponse is attached to the result's grounding field — no separate verifier.verify(text, sources) call needed. On the default runtime, session.send() also checks its reply and session.stream() exposes a grounding promise that runs after its text completes. Direct stream() and GMI session calls do not verify. When the retriever returns no sources, or retrieval or the verifier fails, grounding stays unset and the answer is returned as generated.

Pass a config object with the embedding function and the source retriever the verifier should use:

Example

const docsAgent = agent({
  provider: 'openai',
  model: 'gpt-4o',
  verifyCitations: {
    embedFn: async (texts) => (await embeddingManager.generateEmbeddings({ texts })).embeddings,
    retrieve: (query) => retriever.search(query),
  },
});

const result = await docsAgent.generate('How do I configure a guardrail?');
console.log(result.text);
console.log(result.grounding?.overallGrounded);

}
