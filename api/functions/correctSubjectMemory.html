Function correctSubjectMemory

  • correctSubjectMemory(options): Promise<{
        deleted: number;
        pagesDeleted: number;
        correctionTraceId: string;
    }>

  • Corrects one subject's memory: each page compiled from a named trace is deleted and built again by the subject's next compile, from the traces of it that are left and the correction; the corrected statement is filed as a trace tagged correction; the named traces are deleted for good; and the vector index and the store's write-ahead log are written out (Memory.finishErasure). A deleted trace cannot come back in a later compile, which is why a correction deletes instead of editing a page.

    The named traces go last, so a correction that failed partway is finished by the same call made again: it still finds them. An index rewrite or a log checkpoint that fails does not fail the call; one memory.erasure_unfinished line says so, and the next deletion, sweep or re-application of the tombstones runs it.

    Every named id must be one of the subject's own live traces (a page's chunk is not one): when any is another subject's, unknown or already deleted, the call rejects with a count and nothing is changed.
