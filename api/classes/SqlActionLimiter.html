Class SqlActionLimiter

ActionLimiter over a @framers/sql-storage-adapter store. Counts are rows in the host's database, so they are shared between processes and survive a restart. They are not atomic across two rules: each rule reserves in its own transaction, and a denial gives back the units taken before it, without counting one of the action's attempts.

Someone must run reconcile (or startReconciler in one process): a reservation whose lease ran out counts against its window, and keeps its action a duplicate, until a pass settles it as used.

purge

  • purge(before): Promise<void>

  • Deletes settled reservations. Each meter deletes only those settled before both before and one of its own windows back, so no unit a window still counts is deleted and an allowance never reopens early. An action whose rows are gone is no longer a duplicate, so before is also how long a repeated action reads as one. A meter deletes a page of rows a pass, and is asked again until a pass deletes less than a page.

forgetTarget

  • forgetTarget(accountId): Promise<void>

  • Deletes the rows of every target-scoped rule whose key is exactly <rule id>|t:<accountId> (and its dry: twin), in each meter's two tables, for a host's account deletion. An exact comparison per rule, never a pattern: an id may hold _, which a LIKE reads as any character. A reservation still reserved stays, with its key's window row, so the action that holds it settles its own row and the same action cannot be reserved again while it runs; a host calls this again once that action has ended, or one lease and a reconcile pass later for a process that stopped.
