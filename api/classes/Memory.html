Class Memory

Unified public API for the AgentOS memory system.

One Memory instance manages the full lifecycle of an agent's memories: storing, retrieving, ingesting documents, building a knowledge graph, self-improving through consolidation, and importing/exporting data.

Quick start

const mem = await Memory.create({ store: 'sqlite', path: './brain.sqlite' });

await mem.remember('The user prefers dark mode');
const results = await mem.recall('dark mode preference');
console.log(results[0].trace.content);

await mem.close();

recall

  • recall(query, options?): Promise<ScoredTrace[]>

  • Search for memory traces matching a natural-language query.

    Uses FTS5 full-text search with the Porter tokenizer, ranked by strength * abs(fts_rank). With the HNSW index active and an embedder, the vector index's candidates and the full-text ones are fused by reciprocal rank. The filters bind both halves: a trace of another type, scope or scope id, weaker than minStrength or outside after and before is never returned, however near its vector.

    Parameters

    • query: string

      Natural-language search query.

    • Optional options: RecallOptions

      Optional filters (limit, type, scope, scopeId, minStrength, after, before).

    Returns Promise<ScoredTrace[]>

    Ranked array of ScoredTrace results. A call with no scope and no scope id reads the whole brain, every subject's conversation traces among them: the host's own read of its store. No turn, tool or prompt of a souled agent makes one; pass the scope and a key to read one subject.

    Throws

    TypeError when options.scope is 'conversation' and no scopeId is given: the conversation scope holds each subject's memory under a key of its own and is read one key at a time, never as a whole.

deleteScope

  • deleteScope(scope, scopeId, options?): Promise<{

    }>

  • Deletes every trace of one scope for good: the rows, their memory-graph nodes and knowledge-graph copies, and the full-text index entries. With turnUserId, only the scope's traces whose metadata names that user, as the second user a memory write on another user's session records, or among the contributors of a summary the rolling-summary sink filed. deleteTraces

  • deleteTraces(traceIds, options?): Promise<{
        deleted: number;
    }>

  • Deletes the given traces for good, as deleteScope does for a scope. The rows that name a trace go first, as the Brain's foreign keys require: its retrieval_feedback rows are deleted, and a document_chunks row it was filed from lets go of it and keeps its text. Each trace's memory-graph node goes with its edges, whichever facade on the Brain wrote them, a relation a host made to the node (addRelation) included. Each trace's knowledge-graph copy goes before its row. Unknown ids are skipped.

    With documentChunks: 'delete' the document chunks the traces were filed from are deleted with their text, the pictures of those chunks, and each document left with no chunk: a person's deletion and the retention sweep pass it. On an adapter with transactions those deletes share one, so a failure among them deletes none and a later call finds them again.

writePageRow

  • writePageRow(scopeId, page): Promise<{
        chunkIds: string[];
    }>

  • Writes one wiki page row of a user's or a session's conversation scope, with its chunks. With chunks, the page's old chunks are deleted for good, the new ones are filed as traces under the scope's key with the tags wiki and page:<id>, and the row lists them; without, the row's content is replaced and its chunks are kept. With chunks and keepChunksIfUnchanged, the stored row is compared once the scope's earlier page writes have settled: a row whose contentHash is the one given keeps its chunks, and any other row gets the new ones. The scope's registry row, the new chunks, the page row and the delete of the old chunks are one transaction where the adapter has them; where it has none they run in that order, so the row never lists a chunk that is not stored. The row is replaced only while it holds the text and the chunks the write read: a writer in another process that changed it meanwhile makes the write read it again and start over, so no chunk that writer filed is left unlisted.

compileWiki

  • compileWiki(opts?): Promise<WikiCompileResult>

  • Compile new traces into wiki pages, one conversation scope at a time: each scope's traces go to the compiler with that scope's own page store, and each scope keeps its own watermark, compiled_at in its row of memory_scopes. No-op when no wiki is attached.

    Only the scopes of a user or a session are compiled; the operator's scope never is. For each scope the traces stored after its watermark are read oldest first, in batches. The scope's own page chunks (tagged wiki) are left out, so a scope whose only new traces are its chunks makes no model call. The watermark then moves to the newest trace of the batch read, not to wall-clock now.

    A scope whose compile throws keeps its watermark where it was, so the next compile takes up the same traces, and the other scopes go on. When the wiki's compileSkipReasonOf names a reason for the error, such as a spend budget's refusal, the scope is skipped; any other error is thrown once every scope has run, the first of them when several scopes failed. A scope the wiki's beforeScopeCompile skips keeps its watermark too. Each reason a scope was skipped for is logged once a call, as one memory.compile_skipped line that names no scope.

export

  • export(outputPath, options?): Promise<ExportResult>

  • Export the memory store to a file or directory.

    Format is detected from options.format or the file extension:

    • .json -> JSON
    • .sqlite / .db -> a new SQLite file holding this brain's own rows
    • directory path -> Markdown or Obsidian (based on options.format)

    A SQLite export writes this brain's rows of every portable table, from a SQLite or a Postgres brain; another brain in the same database is left out. Nothing may exist at outputPath yet.
