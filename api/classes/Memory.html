Class Memory

Unified public API for the AgentOS memory system.

One Memory instance manages the full lifecycle of an agent's memories: storing, retrieving, ingesting documents, building a knowledge graph, self-improving through consolidation, and importing/exporting data.

Quick start

const mem = await Memory.create({ store: 'sqlite', path: './brain.sqlite' });

await mem.remember('The user prefers dark mode');
const results = await mem.recall('dark mode preference');
console.log(results[0].trace.content);

await mem.close();

recall

  • recall(query, options?): Promise<ScoredTrace[]>

  • Search for memory traces matching a natural-language query.

    Uses FTS5 full-text search with the Porter tokenizer, ranked by strength * abs(fts_rank). With the HNSW index active and an embedder, the vector index's candidates and the full-text ones are fused by reciprocal rank. The filters bind both halves: a trace of another type, scope or scope id, weaker than minStrength or outside after and before is never returned, however near its vector.

    Parameters

    • query: string

      Natural-language search query.

    • Optional options: RecallOptions

      Optional filters (limit, type, scope, scopeId, minStrength, after, before).

    Returns Promise<ScoredTrace[]>

    Ranked array of ScoredTrace results.

restoreTrace

  • restoreTrace(traceId, before): Promise<void>

  • Brings one trace back to the state a snapshot holds (readTraceSnapshot): its content, tags, scope and metadata, live again. A ledger revert of a memory tool's update, delete or merge calls it with the before-state its row recorded; a revert of an add calls forget. The full-text index then matches the restored words: SQLite rebuilds its index, and Postgres re-indexes the restored row alone.

    A snapshot read before the Brain was re-filed in the encoded scope-id form (ensureEncodedScopeIds) is written under the encoded id, as the re-file wrote the row: once the Brain holds the record, the plain form of an id that holds a / names a namespaced user (team/ana is user ana of namespace team), so the trace stays the plain user's. On Postgres the restore reads the record under the lock a re-file takes, so a re-file another process makes meanwhile comes before or after it.

    Parameters

    • before: TraceSnapshot

    Returns Promise<void>

    Throws

export

  • export(outputPath, options?): Promise<ExportResult>

  • Export the memory store to a file or directory.

    Format is detected from options.format or the file extension:

    • .json -> JSON
    • .sqlite / .db -> a new SQLite file holding this brain's own rows
    • directory path -> Markdown or Obsidian (based on options.format)

    A SQLite export writes this brain's rows of every portable table, from a SQLite or a Postgres brain; another brain in the same database is left out. Nothing may exist at outputPath yet.

    A Markdown or Obsidian export writes one file per trace, in folders named after the trace's scope and type, and leaves out a trace whose scope, type or id is not a safe file or folder name, whose place in the export folder holds a link, symbolic or hard, or anything but a regular file, or whose file would be an older trace's, where names ignore case or by the file system's own reckoning; the result lists each one left out. No file is written outside the export folder.

    Parameters

    • outputPath: string

      Path to write the export to.

    • Optional options: ExportOptions

      Optional format and content controls.

    Returns Promise<ExportResult>

    The traces the export left out, with the reason for each.

createTools

  • createTools(options?): ITool<any, any>[]

  • Create runtime ITool instances backed by this memory facade's SQLite brain.

    This is the supported bridge from the standalone memory engine into AgentOS tool registration. The returned tools share this Memory instance's underlying SQLite database and consolidation loop.

    Typical usage:

    for (const tool of memory.createTools()) {
      await agentos.getToolOrchestrator().registerTool(tool);
    }

    Where a learning layer puts a turn's scope ids on a call, the tools file and read under them and record each write in the layer's ledger, and memory_reflect refuses (withdrawn); a host that registers the tools itself leaves memory_reflect out (includeReflect: false).

    When self-improvement is disabled, memory_reflect is omitted because there is no backing ConsolidationLoop instance.
