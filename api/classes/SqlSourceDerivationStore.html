Class SqlSourceDerivationStore

Durable private provenance on PostgreSQL. All source writers use this owner fence; model/provider work stays outside it. No method logs SQL, content or exceptions.

Every method that reads or writes an owner's results runs in one transaction that first locks that owner's fence row, so commits, deliveries, invalidations and expiry for one owner are serialized, while different owners proceed independently. Writing a deletion record also locks one shared journal row, last, so the records' sequence follows commit order.

Example

const store = new SqlSourceDerivationStore(db, { bindings });
const ticket = await store.capture({ tenantId, ownerId });
// ...generate an answer outside the store...
if (ticket && await store.commit(ticket, answerId, derivation, answerText, context)) {
  await store.deliver(answerId, context, (text) => {
    queue.push(text);
    return true;
  });
}

invalidate

  • invalidate<T>(scope, affected, mutate, options?): Promise<SourceFencedResult<T>>

  • Advance the fence, purge affected sources and all whole dependent results, and mutate host state in one transaction. A supplied expected ticket is a CAS.

    With expected, an inactive owner or an epoch past the ticket's answers stale without purging or entering mutate. Without it, the invalidation always applies, also to an inactive owner, which stays inactive. disableOwner leaves the owner inactive and needs an owner-wide invalidation. A thrown binding or mutate rolls back the epoch, the purge and the deletion record together.
